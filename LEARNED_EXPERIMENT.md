# First experiment: learned tracking evidence and boundary-aware segmentation

This is a separate experimental pipeline. The original `possession/` v6 model,
submission generator and official scorer are unchanged. No improvement over v6 has
been established. A private Kaggle run has now prepared all 199,319 real-match
frames and completed the public-window smoke experiment. On its two-minute
evaluation portion, learned spellF1 was **0.2154**, versus **0.5818** for v6. This
confirms the pipeline runs; it gives no reason to replace v6. Broader independent
labels are the next step; see [ANNOTATION_WORKFLOW.md](ANNOTATION_WORKFLOW.md).

A second private run used a supplied partial draft session: the public reference
plus bounded second-half annotations for training, and bounded first-half
annotations for provisional validation. On those same 163.12 validation seconds
(9 labelled possessions), the new learned model scored **0.5556 spellF1 / 0.6489
macro F1**, versus **0.4842 / 0.4984 for v6** and **0.3333 / 0.5157 for the previous
learned model**. No parameter search was performed. The annotations remain drafts,
their unmarked prefixes/open tails remain X, and calibration missed a short
public stoppage, so this is not evidence of a verified full-match improvement.
The originally reserved first-half test window became provisional validation;
there is no final-test score. All 21 tests passed, annotation exports reproduced
exactly, and the saved model regenerated byte-identical predictions. See the
partial-draft workflow and `notebooks/possession_draft_kaggle.ipynb` for reproduction.

The first model runs on CPU. Kaggle's GPUs will be useful for a later temporal
network and video experiments; this small baseline establishes whether supervision
and boundary-aware decoding help before using that budget.

## What is implemented

1. `learned_possession/features.py` builds per-frame, label-free features from the
   tactical assets: visibility, ball motion, line distances, nearest three players
   per team, local pressure counts, player activity/spread, whistles and tag priors.
   Centred 1/3/5-second summaries supply offline context and do not cross halftime.
   Missing coordinates stay NaN, with explicit visibility indicators. Goalkeeper
   team correction is reused from v6.
2. `model.py` trains separate histogram gradient-boosted classifiers for H/A/D and
   label boundaries. There is no random internal validation split, class-frequency
   reweighting or pseudo-labelling from v6. Probabilities are not calibrated yet.
3. `segment.py` scores whole segments using cumulative state evidence, learned
   boundary scores and weak duration preferences. A dynamic programme chooses the
   best segmentation on a candidate-boundary graph. Candidates include a one-second
   fallback grid, state-argmax changes and peaks of the boundary classifier.
   There is **no hard minimum possession or stoppage length**. Each half is decoded
   independently; X is written outside the halves.
4. The CLI caches features, trains/evaluates, saves a model and report, compares
   baselines on the **same validation frames**, and regenerates predictions from
   the saved model. Outputs go to paths supplied explicitly, not tracked reports.

The decoder optimises a surrogate, not spellF1 itself:

```
sum(segment log-state evidence / fps)
  - switch_cost per change
  + boundary_weight * log(boundary probability) at each change
  - duration_weight * soft log-duration penalty
```

Duration preferences are fitted on complete **training** segments only, excluding
segments cut by annotation windows. Classes with fewer than three complete
examples get no duration preference. Half-edge segments are treated as censored.
Defaults are starting points, not tuned football parameters.

The decoder is exact for its candidate graph. `--grid-frames 1` includes every frame,
but quadratic work makes it unsuitable for full halves. Normal runs use the coarse
grid plus precise candidates from predictions. A candidate-count limit fails with
an explanation instead of silently doing an unexpectedly costly run or deleting
possible boundaries. Full-match runtime remains to be measured.

## Inputs and labels

Keep the match bundle private, with this layout:

```
<data-root>/tactical/BAR-ATH_tactical.mp4
<data-root>/tactical/BAR-ATH_tactical_atd.xml
<data-root>/tactical/BAR-ATH_tactical_atd.txt
<data-root>/tactical/BAR-ATH_tactical_homography.csv
<data-root>/tactical/BAR-ATH_tactical_smart_tagging.xml
```

The pipeline reuses v6's feature-generation helpers, including audio extraction,
so **all five tactical assets are required**. Read-only Kaggle inputs are supported:
parser and audio caches are redirected to a writable folder beside the feature
cache and scoped by source size/mtime metadata. This is cache invalidation, not a
cryptographic verification of the raw inputs. The portable feature file records
source metadata and uses NPZ with pickle disabled.

For an honest experiment, provide two full-length `frame,label` CSVs with X outside
the annotated windows: one for training and one for validation. Use several windows
from both halves and start/end them in stoppages where possible. A useful aim is
20–30 minutes of labels including both representative and difficult play. The
existing `tools/label_tool.py` can create/export these files. Manual labels are
allowed for training/validation; predictions must still come from the algorithm.

The trainer rejects overlapping training/validation frames, drops labels outside
the halves, and purges training frames within 10 seconds of validation by default.
Purging cannot be below 3 seconds because the features use centred context. Each
training set must include H, A and D and usable label changes. Validation is not
used to fit the classifiers, durations, stopping criterion or calibration. Reserve
another untouched set of windows if this validation set is later used to choose
hyperparameters. A fixed seed does not make the public five minutes representative.

## Run locally or on Kaggle

Python 3.11+ is required for the pinned experimental stack. Install this separately
from v6's exact reproduction environment:

```bash
python -m pip install -r requirements-learning.txt
python -m unittest discover -s tests -v
python -m learned_possession prepare --data-dir /path/to/data --out /path/to/work/features.npz
python -m learned_possession train \
  --features /path/to/work/features.npz \
  --train-labels /path/to/train.csv \
  --validation-labels /path/to/validation.csv \
  --compare evaluation/results/possession_v6.csv evaluation/results/baseline_smooth50.csv \
  --out /path/to/work/run01
python -m learned_possession predict \
  --features /path/to/work/features.npz \
  --model /path/to/work/run01/model.joblib \
  --out /path/to/work/regenerated.csv
```

Training writes `model.joblib`, `learned.csv`, `report.json` and `versions.json`.
The report includes cache/label hashes, training counts, decoder settings, validation
spellF1/macroF1 and bootstrap intervals, and optional baseline results. The predict
command uses the saved decoder settings and does not read labels. Model files use
joblib and should be loaded only from your own trusted training runs.

### If additional labels are not ready

```bash
python -m learned_possession public-smoke \
  --features /path/to/work/features.npz \
  --compare evaluation/results/possession_v6.csv \
  --out /path/to/work/public-smoke
```

This fixed smoke run trains on the first three public minutes and evaluates the
last two, with temporal purging. It exercises real feature preparation, fitting,
decoding and scoring. **It is not an independent benchmark:** the public labels
were already used in v6 development. Do not select hyperparameters from this split
or describe its score as evidence that the model beats v6 on the full match. The
smoke output is not the proposed final competition submission.

### Kaggle notebook

Import `notebooks/learned_possession_kaggle.ipynb`. Attach your private match dataset
and the experiment source bundle as notebook inputs. Internet is needed for the
initial dependency installation. The notebook discovers the tactical folder and
source ZIP, writes under `/kaggle/working/possession_experiment`, runs tests, caches
features, then performs the selected public smoke or separately labelled run.
Configuration is in its first code cell. Keep mode `public-smoke` until genuinely
separate training and validation label files are supplied.

After a successful run, save/download the feature cache and run artifacts using
Kaggle's output/version controls before the session ends. Reuse the feature cache
for later parameter experiments; decoder comparisons do not need to re-decode audio.

## Validation completed here

The test suite verifies the dense decoder against exhaustive enumeration, recovery
of synthetic short possessions and quick stoppages, invalid-input rejection,
temporal purging, unknown-label boundary handling, censored duration fitting,
missing-ball features, halftime isolation, cache roundtrip, and end-to-end CLI
training/evaluation/save/reload with byte-identical regenerated predictions.

The first real Kaggle smoke run completed on CPU, passed the implementation tests,
and regenerated byte-identical predictions from the saved model. Its training
portion had just one 5.52-second D segment, so this tiny split poorly represents
stoppages. No performance gain or GPU benchmark is claimed. The next comparison
is the learned model versus v6 on the same independently reviewed windows, followed
by a temporal-network trial if that evidence supports it.
